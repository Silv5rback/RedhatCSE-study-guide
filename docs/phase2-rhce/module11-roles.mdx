# Phase 2, Module 11 — Ansible Roles

## Theory

Roles are Ansible's way of grouping related tasks, variables, files, templates, and handlers into reusable units:

- **Role structure** — Standard directory layout (`tasks/`, `handlers/`, `templates/`, `files/`, `vars/`, `defaults/`, `meta/`)
- **ansible-galaxy** — Download and share roles from Galaxy (`ansible-galaxy install`)
- **Role dependencies** — `meta/main.yml` defines required roles
- **Using roles** — `roles:` in a play, `import_role`, `include_role`

**Exam reality:** You'll create roles to organize your RHCE exam playbooks. Roles make your code modular and reusable across multiple plays.

## Try It

```bash
# Create a role with ansible-galaxy
ansible-galaxy role init common

# Or create manually:
# common/
#   tasks/main.yml
#   handlers/main.yml
#   templates/
#   files/
#   vars/main.yml
#   defaults/main.yml
#   meta/main.yml

# Install a role from Galaxy
ansible-galaxy install geerlingguy.apache

# Use a role in a playbook
---
- hosts: webservers
  become: yes
  roles:
    - geerlingguy.apache
    - common
```

## Guided Lab

1. **Initialize a role**
   ```bash
   mkdir -p ~/ansible/roles
   cd ~/ansible/roles
   ansible-galaxy role init webserver
   ```

2. **Explore the role structure**
   ```bash
   find webserver -type f
   ls -la webserver/
   ```

3. **Write role tasks**
   ```yaml
   # ~/ansible/roles/webserver/tasks/main.yml
   ---
   - name: Install httpd package
     ansible.builtin.package:
       name: "{{ web_package | default('httpd') }}"
       state: present
   
   - name: Configure httpd port
     ansible.builtin.lineinfile:
       path: /etc/httpd/conf/httpd.conf
       regexp: "^Listen "
       line: "Listen {{ web_port | default(80) }}"
     notify: restart httpd
   
   - name: Ensure httpd is started and enabled
     ansible.builtin.service:
       name: "{{ web_service | default('httpd') }}"
       state: started
       enabled: yes
   ```

4. **Write role handlers**
   ```yaml
   # ~/ansible/roles/webserver/handlers/main.yml
   ---
   - name: restart httpd
     ansible.builtin.service:
       name: httpd
       state: restarted
   ```

5. **Write role defaults**
   ```yaml
   # ~/ansible/roles/webserver/defaults/main.yml
   ---
   web_package: httpd
   web_service: httpd
   web_port: 80
   ```

6. **Write role vars**
   ```yaml
   # ~/ansible/roles/webserver/vars/main.yml
   ---
   web_document_root: /var/www/html
   ```

7. **Add a template file**
   ```jinja2
   # ~/ansible/roles/webserver/templates/index.html.j2
   <h1>Welcome to {{ ansible_hostname }}</h1>
   <p>Managed by Ansible role: webserver</p>
   ```

8. **Add a static file**
   ```bash
   # ~/ansible/roles/webserver/files/custom-script.sh
   #!/bin/bash
   echo "Custom script from webserver role"
   ```

9. **Write role meta (dependencies)**
   ```yaml
   # ~/ansible/roles/webserver/meta/main.yml
   ---
   galaxy_info:
     author: RHCE Student
     description: Web server role
     license: MIT
     min_ansible_version: "2.9"
     platforms:
       - name: EL
         versions:
           - "9"
   dependencies: []
   ```

10. **Use the role in a playbook**
    ```yaml
    # ~/ansible/site.yml
    ---
    - name: Configure all servers
      hosts: all
      become: yes
      roles:
        - role: webserver
          vars:
            web_port: 8080
            web_package: httpd
    ```

11. **Run the playbook**
    ```bash
    ansible-playbook -i ~/ansible/inventory.ini ~/ansible/site.yml
    ```

12. **Install a role from Galaxy**
    ```bash
    ansible-galaxy install geerlingguy.apache
    ```

13. **Use a Galaxy role**
    ```yaml
    # ~/ansible/site.yml
    ---
    - hosts: webservers
      become: yes
      roles:
        - geerlingguy.apache
        - role: webserver
          vars:
            web_port: 8080
    ```

**Expected output:** Roles are created, installed from Galaxy, and used in playbooks. Playbooks run successfully with role variables.

:::tip Exam Tip
Role defaults (`defaults/main.yml`) have the lowest precedence and can be overridden by playbook vars. Role vars (`vars/main.yml`) have higher precedence.
:::

## Quiz

<details>
<summary><strong>Q1: Which directory in a role contains the main task list?</strong></summary>
<p><strong>Answer:</strong> `tasks/main.yml` contains the role's primary task definitions.</p>
</details>

<details>
<summary><strong>Q2: Which command installs a role from Ansible Galaxy?</strong></summary>
<p><strong>Answer:</strong> `ansible-galaxy install <username>.role_name` downloads a role from Galaxy.</p>
</details>

<details>
<summary><strong>Q3: Which file defines role dependencies in meta/main.yml?</strong></summary>
<p><strong>Answer:</strong> The `dependencies:` list in `meta/main.yml` defines roles that must be installed first.</p>
</details>

:::tip Exam Tip
Use roles to organize exam playbooks. One role per functional area (webserver, database, firewall, monitoring) keeps your code clean.
:::
