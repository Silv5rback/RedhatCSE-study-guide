# Phase 2, Module 14 — RHCE Capstone

## Theory

This capstone simulates an RHCE-style (EX294) exam environment. You'll write Ansible playbooks and roles that configure multiple systems to meet requirements:

**Exam format:** The RHCE (EX294) is a 3-hour, hands-on performance exam. You're given:
- A control node with Ansible installed
- Several managed nodes (RHEL systems)
- An inventory file
- A list of requirements

You must write Ansible code that configures the managed nodes to meet all requirements.

**Key exam skills:**
- Writing idempotent playbooks and roles
- Using Ansible Vault for secrets
- Managing packages, services, users, storage, firewalld, SELinux
- Using Jinja2 templates for dynamic config
- Debugging playbooks that fail
- Working with existing inventory and SSH access

**Scoring:** Each requirement is worth points. You typically need 70% to pass.

## Guided Lab — RHCE Capstone Scenario

### Requirements

You're given a control node and 2 managed nodes (`web01`, `db01`). Complete these tasks:

**Task 1: Web Server Role (45 minutes)**
Create a role `webserver` that:
- Installs `httpd` package
- Creates document root `/var/www/html`
- Deploys `index.html` from a Jinja2 template with `{{ ansible_hostname }}`
- Ensures `httpd` service is started and enabled
- Opens port 80 in firewalld
- Sets SELinux context for `/var/www/html`
- Applies only to hosts in `[webservers]` group

**Task 2: Database Role (45 minutes)**
Create a role `database` that:
- Installs `postgresql-server` package
- Initializes PostgreSQL database
- Ensures `postgresql` service is started and enabled
- Opens port 5432 in firewalld
- Sets a vaulted password for the postgres user
- Applies only to hosts in `[dbservers]` group

**Task 3: Common Configuration (30 minutes)**
Apply to all hosts:
- Creates user `ansible-admin` with sudo access
- Sets SSH key for `ansible-admin`
- Ensures SELinux is enforcing
- Configures NTP/chrony
- Installs `vim`, `curl`, `wget`

**Task 4: Vault Secrets (15 minutes)**
- Create `vault.yml` with database passwords
- Use vaulted variables in the database role
- Run playbook with `--ask-vault-pass`

### Solution Structure

```
~/ansible/
├── inventory.ini
├── site.yml
├── vault.yml
├── roles/
│   ├── webserver/
│   │   ├── tasks/main.yml
│   │   ├── handlers/main.yml
│   │   ├── templates/index.html.j2
│   │   └── defaults/main.yml
│   └── database/
│       ├── tasks/main.yml
│       ├── handlers/main.yml
│       ├── defaults/main.yml
│       └── vars/main.yml
└── .vault_pass
```

### Verification

```bash
# Run the full playbook
ansible-playbook -i inventory.ini site.yml --ask-vault-pass

# Verify on web01
ansible web01 -i inventory.ini -a "systemctl status httpd"
ansible web01 -i inventory.ini -a "cat /var/www/html/index.html"
ansible web01 -i inventory.ini -a "firewall-cmd --list-all"

# Verify on db01
ansible db01 -i inventory.ini -a "systemctl status postgresql"
ansible db01 -i inventory.ini -a "getenforce"

# Verify on all
ansible all -i inventory.ini -a "id ansible-admin"
ansible all -i inventory.ini -a "getenforce"
```

:::tip Exam Tip
Read all requirements before writing any code. Plan your role structure, then write tasks, templates, and variables. Test incrementally.
:::
